三、调用 refresh 方法

------------重点方法一----------------

invokeBeanFactoryPostProcessors(beanFactory); 

这个方法会将所有的bean（除了上面已经处理过的 annotatedClasses）实例化成 BeanDefinition 对象，保存在 beanDefinitionMap 当中

------------重点方法二----------------

registerBeanPostProcessors(beanFactory); 

遍历所有的bean definition名称，返回能匹配上 BeanPostProcessor.class 类型的 postProcessorNames，然后通过这些 postProcessorNames 去 BeanFactory 获取bean (getBean)，如果没有，就实例化 (createBean)。

一般这时候自定义的 BeanPostProcessor 会完成实例化工作，最后会将这些实例化好后 BeanPostProcessor 放到 BeanFactory 中的 beanPostProcessors（ArrayList<BeanPostProcessor>）属性中。

----------重点方法三-------------------

finishBeanFactoryInitialization(beanFactory)



接着调用 beanFactory.preInstantiateSingletons();



循环 beanDefitionNames 时（bean name），调用 getBean(beanName)



getBean 里面调用 createBean，

接下来有个特殊情况如果是普通bean，接着调用 doCreateBean()；

以下接着 doCreateBean 方法：

**1、首先调用 createBeanInstance 方法来完成实例化工作**

- 如果是通过Java代码装配bean定义，会通过反射调用该类方法完成 bean 实例化工作

调用链：instantiateUsingFactoryMethod（这里的factory指的是该方法所在的配置类） -> this.beanFactory.getInstantiationStrategy().instantiate -> factoryMethod.invoke（这里就会调用这个student方法）

如果说**有依赖，会先不光实例化，还会初始化依赖（意味着“依赖”的全部准备工作都已经就绪）**

所以说 factoryMethod.invoke方法调用返回后的实例对象（student）它的依赖是有确切值的（student.studentDependency != null）。

```
@Bean
public Student student(StudentDependency studentDependency) {
	return new Student();
}

@Bean
public StudentDependency studentDependency() {
	return new StudentDependency();
}
```

- 如果是通过自动扫描装配bean定义，会通过调用构造方法来完成实例化

调用链：instantiateBean -> getInstantiationStrategy().instantiate -> BeanUtils.instantiateClass(constructorToUse) -> ctor.newInstance(args)

这个时候 student.studentDependency == null

```
@Component
public Class Student {
	@Autowired
	private StudentDependency studentDependency;
}
```

*解决bean的循环依赖问题*：

三个缓存概念对象：

- 一级缓存，所有的成熟bean，既实例化了，又初始化了。singletonObjects
- 二级缓存，原生的早期bean，实例化了，但没有初始化。earlySingletonObjects
- 三级缓存，用来生成代理bean的工厂。singletonFactories

比如：A -> B，B -> A

过程：A instantiate -> A 加入 early reference -> populate 发现依赖B -> doGetBean(B)，从一级缓存查，没有；从二级缓存查，也没有

-> B instantiate，加入 early reference，设置对象属性，populate 发现依赖A -> doGetBean 获取 A，从一级缓存查没有；从二级缓存查获取到 early reference -> B 初始化完成并加入一级缓存

-> A 初始化完成并加入一级缓存

**2、调用 populateBean 完成 bean 属性配置**

上述的通过Java代码配置bean定义的方式，populateBean 不会起任何作用，已经属性已经在实例化的时候，按照Java代码想要的方式已经实例化好了。

上述的通过自动扫描装配bean定义的方式，会通过系统内置的各种 BeanPostProcessor 比如 AutowiredAnnotationBeanPostProcessor（处理@Autowired注解的属性） 来对对象属性赋值。这里就会为依赖的对象set值。

**3、继续调用 initializeBean 方法来完成初始化工作**

里面调用3个方法：

1、applyBeanPostProcessorsBeforeInitialization。需要注意的是众多beanPostProcessor before的处理里面会有一个系统内置的 CommonAnnotationBeanPostProcessor（构造方法：*setInitAnnotationType(PostConstruct.class)*） 用来调用 @PostContruct 注解的方法。

2、invokeInitMethods，先调用 ((InitializingBean) bean).afterPropertiesSet()，再调用 invokeCustomInitMethod

3、applyBeanPostProcessorsAfterInitialization

这3个方法说明了一些初始化组件的调用顺序：BeanPostProcessor的 before 方法（包括 @PostConstruct），InitializingBean 的 afterPropertiesSet，本身的 init 方法，BeanPostProcessor 的 after 方法。

**4、registerDisposableBeanIfNecessary**

如果是该bean实现了DisposableBean接口的话，调用 registerDisposableBean 给这个bean注册一个 DisposableBeanAdapter（该类实现了DisposableBean），

然后将该 adapter 加入到名字为 disposableBeans 的 LinkedHashMap 中，key为beanName。

这个操作和销毁密切相关。

doCreateBean 结束后，实例化+初始化好了一个全新的单例bean对象，调用 addSingleton 方法将该bean添加到 singletonObjects 里面去。

终于可以宣告结束啦！

**销毁**：

applicationContext.close() - > doClose() -> destroyBeans() -> destroySingletons 

-> 然后循环  disposableBeans 获取其中的beanName -> destroySingleton(beanName) 

-> destroyBean(String beanName, DisposableBean bean[实际上为上面介绍到的DisposableBeanAdapter]) -> bean.destroy();
