```
git fetch --all
git fetch remotename
git fetch remotename(origin) branchname


git checkout -b localbranch remotename/remotebranch
git checkout localbranch // 切换分支

git merge remotename/branchname
 - git fetch & merge 可以用git pull remotename remotebranch:localbranch 代替
 - 如果 merge 冲突，解决冲突后，add 再 commit 即可


git add .

git commit -m 'commit msg'

git push remotename branchname

git push remotename localbranch:remotebranch // 本地分支推到不同名远程分支上


git branch -d locanbranch // 删除本地分支
```

撤销提交/回退

```
# 待add
git checkout -- <file>


# 待commit
git reset HEAD <file>


# 待push
git log
git reset commit_id_you_want_to_back_to   保留本次commit文件修改的内容
git reset --hard commit_id_you_want_to_back_to  不保留文件修改的内容


# 已push
git log --pretty=oneline --abbrv-commit

方案一：
git revert commit_id_you_want_to_revert 已经push上去的那次commit id
git push
缺陷：假设revert了A文件，由于revert相当于更新文件（比如新增，删除），当其他分支在该revert时间点前更新了A文件（正确的操作），可能会导致其他分支merge到该分支上时，发现他们自己的更改没有了，因为git会认为你revert之后的提交是修改后最新的。

方案二：
git reset --hard commit_id_you_want_to_back_to
git push --force
缺陷：慎用。你reset完了，该分支其他合作者本地会出现两个问题。
1、假如你reset了不光自己的错误提交，还有别人在你之后的提交，其他合作者会pull不下来，造成困惑；
2、其他人直接push的话，仍然会将你reset的东西推送上去，相当于白做了（所以其他合作者都要reset本地分支）
如果是错误提交了密码之类的敏感信息，适合用reset方案

方案一是revert后形成一次新的提交，历史记录里面还是可以看到以前的提交。
方案二是回到想要回到的commit上，然后删除之前的所有提交。但git push --force有一定的危险，如果在你--force之前，其他人提交了，那么--force之后，其他人的提交记录也将一块儿丢掉。
```

如果合并错了目标分支，并push上去这种行为，没有完美的回滚解决方案，不如删了目标分支让大家重新合
