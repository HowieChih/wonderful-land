#### group_concat
``concat`` 函数可以将一行多个字段拼接在一起
``group_concat`` 函数可以将多行一个字段拼接在一起

```SQL
select group_concat(student_name separator ',') from class where class_name = "A";

select class_name, group_concat(student_name separator ',') from class group_by class_name;
```

#### Not In

假设表里user_no 有 a b c 三个值

表里的数据not in指定集合

```
select * from user where user_no not in ('a', 'b');

-- 结果 c
```

指定集合的数据not in表里

```
SELECT
    t.user_no
FROM (select 'a' as user_no from dual
            union  
            select 'b' as user_no from dual  
            union  
            select 'd' as user_no from dual
      ) AS t
WHERE
    t.user_no NOT IN (
        SELECT DISTINCT
            user_no
        FROM
            user
        WHERE
            user_no IN (
                'a',
                'b',
                'd'
            )
    );
    

select t.user_no  
  from (select 'a' as user_no from dual
        union  
        select 'b' as user_no from dual  
        union  
        select 'd' as user_no from dual  
        ) t
  left join user  b
    on b.user_no = t.user_no  
where b.id is null;
    
-- 结果 d
```

#### dual

You are permitted to specify DUAL as a dummy(虚拟的) table name in situations where no tables are referenced：

```
select 1+1 from dual;
```

DUAL is purely for the convenience of people who require that all [SELECT](https://dev.mysql.com/doc/refman/8.0/en/select.html) statements should have FROM and possibly other clauses. MySQL may ignore the clauses. MySQL does not require FROM DUAL if no tables are referenced.

#### group_by

- 可以按照多列分组，表示只有多个列都相同的值才会分到一组。
- 如果分组有null值，则null作为一组返回。
- group by必须在where子句之后，order by子句之前。
- group by status desc 按照 status 分组并且排序，默认asc

#### only_full_group_by 选项

MySQL 默认 ``only_full_group_by`` 选项打开

1、group_by 语句中，select list、having condition、order by list 的非聚合字段（nonaggregated columns）

- 是 group_by 的条件字段
- 或者函数依赖（functionally dependent）group_by 的条件字段

该特性源自SQL-92、SQL:1999标准，MySQL的实现基于SQL:1999，支持 functionally dependent

为什么会有这些特性限制？本质的原因是在group_by之后，如果select的字段值不唯一，数据库就无法知道选哪个值作为查询结果。

```
id | name
 1 |  A
 2 |  A
 3 |  B
```

比如上表数据，假设 ``select id, name from user group_by name ``，name = A组有两个id值1和2，最后 id 的查询结果无法决策，会导致查询被拒。

上面提到的两个特性就是为了规范该问题，还有一种解决方案是使用``ANY_VALUE()``函数，不管采用哪种方式方法，本质上都是为了让无法确定结果的字段值变得唯一可确定

````
select any_value(id), name from user group_by name
````

**functionally dependent** 表述为：{*X*} -> {*Y*}

意义：*X* uniquely determines *Y*，which also means that *Y* is functionally dependent on *X*.

所以如果想在group_by的select list里使用非聚合函数字段（假设id，上述 Y），那么该非聚合函数字段必须依赖group_by的条件字段（假设name，上述X），即 name 能唯一决定 id。本质上还是要确认最后结果唯一

假设上述的查询 name 是不为空的唯一索引字段，那么 name  能唯一决定id，MySQL查询会成功执行查询语句。

2、如果一个查询，没有group_by条件，但有聚合函数查询结果

```sql
SELECT a, SUM(b) FROM mytable;
```

假设表里a有多个值，将报错；a只有一个值合法

```
SELECT a, SUM(b) FROM mytable where a = 'legal';
```

通过限定 a = 'legal' 条件，将a的值限定唯一，可以查询

3、拥有 DISTINCT 和 ORDER BY 的查询

| **c1** | **c2** | **c3** |
| ------ | ------ | ------ |
| 1      | 2      | A      |
| 3      | 4      | B      |
| 1      | 2      | C      |

```sql
SELECT DISTINCT c1, c2 FROM t ORDER BY c3;
```

上面这条句子将无法确定c1=1，c2=2时c3的值

order by 的字段必须满足以下两个条件：

- order by 的表达式必须等于 select list当中的一个表达式
- order by 引用的所有字段，必须是查询表中的字段，并且要出现在select list里

#### Identifier Case Sensitivity

| 类型                     | 是否区分大小写？                                             | 说明                                             |
| ------------------------ | ------------------------------------------------------------ | ------------------------------------------------ |
| **数据库名**             | ✅ **在 Unix/Linux 系统上区分大小写**<br />❌ 在 Windows 系统上不区分 | 取决于操作系统的文件系统，因为数据库对应的是目录 |
| **表名**                 | ✅ 同上，**在 Unix/Linux 上区分**                             | 表在磁盘上是文件，文件名区分大小写               |
| **列名**                 | ❌ **不区分大小写**                                           | 在所有平台上都不区分                             |
| **别名**                 | ❌ 默认不区分大小写                                           | 但建议保持一致风格                               |
| **存储过程 / 函数名**    | ✅ **区分大小写**                                             | 在所有平台上都区分大小写（MySQL 5.1+）           |
| **触发器、事件、视图名** | ✅ **区分大小写**                                             | 在所有平台上都区分                               |

系统变量 `lower_case_table_names，决定了表名/数据库名是否大小写敏感：

| 值   | 行为说明                                     | 常见系统        |
| ---- | -------------------------------------------- | --------------- |
| 0    | 表名/数据库名区分大小写（**严格敏感**）      | Unix/Linux      |
| 1    | 不区分大小写，**所有对象都被转换为小写保存** | Windows         |
| 2    | 创建时保留大小写，但比较时不区分（不常用）   | 旧版 MacOS 可用 |
