char在lass加载进入JVM后，在JVM内部的表达就是一个按照UTF-16编码后的**16位整数值**



- UTF-16 在 JVM 内部 是 唯一的字符串语义层格式；
- 它在 进入 JVM 时被确立，在 离开 JVM 时被重新编/解码；
- 中间的所有计算都直接基于这套 16-bit 规则，而不再关心文件编码或物理字节序。

| 环节                        | UTF-16规则具体发挥的作用                                     |
| --------------------------- | ------------------------------------------------------------ |
| 1. 类加载 -> JVM内部        | *解码一次*：<br/>常量池里的 MUTF-8 → **UTF-16 char[]**。<br/>此时 UTF-16 规则（16 bit 单元 + 代理项对）决定 **`char` 的存储结构**。 |
| 2. JVM 运行期所有字符串运算 | *始终依赖* UTF-16：<br/>`length()`、`charAt(i)`、`substring()`、`StringBuilder` 等都按 **16-bit 单元** 处理，遇到增补字符就识别代理项对。 |
| 3. 与外部世界交互 (I/O)     | *再次用到* 规则的反向过程：<br/>• 输出：UTF-16 `char[]` → `CharsetEncoder` → 目标字节集（常见 UTF-8）。<br/>• 输入：字节流 → `CharsetDecoder` → UTF-16 `char[]`。 |
